# Formal companions

A library of formal companions: each puts a mathematical text's PDF beside a Lean formalization of
it. Every numbered statement and display is boxed on the page and linked to the declarations that
state it, with a verdict on whether they say what the text says.

Read them at <https://deicyde.github.io/formal-companions/>.

**Unreviewed machine audits.** AI agents produced the links and verdicts. No mathematician has
checked them unless a companion says so.

## What is here

This repository holds no companion. [`companions.json`](companions.json) is a registry: each entry
names a companion's repository, a full commit and the folder that holds its `pdf-overlay/` and
`annotations/`. [`scripts/build.py`](scripts/build.py) builds the site from those pins.

## How the site is built

For each entry, `scripts/build.py`:
- fetches that commit only, shallow and blobless, and checks out only the companion's folder;
- refuses the companion if its `pdf-overlay/` was generated by a formal-companion commit other than
  the registry's `formal_companion`, so every viewer runs the same version;
- refuses it if its own `pdf-overlay/tools/check_generated.py` fails;
- refuses it if its config sets neither `pdf.remote` nor `pdf.publish`, because such a viewer works
  on loopback only.

It then builds the companion's site with that companion's own tools:
- **`pdf.remote`:** `build_site.py`. The reader's browser fetches the PDF from the address the
  annotations name, and this site holds no copy.
- **`pdf.publish`:** `serve.py --build-only`, for a PDF under an open licence. It fetches the PDF and
  checks its sha256 before publishing it.

The result is copied to `_site/<slug>/`, and the build refuses any other PDF that came with it. Every
viewer checks its PDF's sha256 before showing it. The catalog, `index.html`, and `library.json` take
their titles, authors, Lean targets and counts from each companion's own config and annotations.

```sh
python3 scripts/build.py                  # all of them, into _site/
python3 scripts/build.py --only yang-mills
python3 -m http.server -d _site 8000      # then open http://127.0.0.1:8000/
```

Python 3.11+ and git; standard library only. The Pages workflow runs the same build on every push
to `main`, and on pull requests without deploying.

## Adding or updating a companion

1. In the companion's repository, run formal-companion's `cf overlay sync` at the registry's
   `formal_companion` commit, with `"remote": true` in the `pdf` block of `overlay.config.json`
   (or `pdf.publish` for an openly licensed PDF). Check that `pdf-overlay/tools/check_generated.py`
   passes, and commit.
2. Here, add or update its entry with the full commit, run `python3 scripts/build.py --only <slug>`,
   and open a pull request.

For `pdf.remote`, the PDF's host must allow cross-origin reads. This must show
`access-control-allow-origin`:

```sh
curl -sI -H 'Origin: https://example.org' '<the PDF end's uri>'
```

To move every companion to a new formal-companion version, re-sync each one, then update
`formal_companion` and every pin in one pull request.
